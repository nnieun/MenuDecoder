작성일: 2026-09-09 · Codex 전달용

## 4. 필수 비교 실험 산출물

| ID | 실험 | 비교값·조건 | 반드시 남길 결과 |
| --- | --- | --- | --- |
| EX-01 | 청크 크기 | 256·512·1024 토큰 | 근거 검색·문맥 포함·노이즈·실제 청크 분포 |
| EX-02 | Similarity 대 MMR | 같은 후보 풀·최종 K | 정확성·중복·관련 근거 다양성 |
| EX-03 | 임베딩 | OpenAI 대 BGE-M3 dense | 검색 품질·API 사용량·시간·장비·자원 |

| EX-05 | Hybrid Search | BM25·dense·RRF 결합 | 단독 대비 검색 누락·순위·답변 비교 |
| EX-06 | Reranking | 같은 후보에 적용 전후 | 근거 순위·답변·추가 지연 |
| EX-07 | 환각 완화 | 근거 제한·인용 요구·보류 임계값 | 충실도·인용 적합성·답변율·잘못된 보류 |
| EX-08 | 메모리 | 미사용·최근 대화·요약+최근 대화 | 지시어 해석·답변 품질·문맥 사용량 |
| EX-09 | OCR 비교 | OpenAI 단독·PaddleOCR 결합 | 글자 오류·메뉴명/가격 연결·처리 시간 |
| EX-10 | 자동 사진·전체 흐름 | 실제 메뉴 입력에서 검색·검토·재검색 | 사진 적합성·제공률·실패·전체 지연 |

EX-01~EX-08에서는 정답 메뉴 텍스트와 고정된 수집 문서를 사용하여 OCR·웹 변동과 검색 설정의 효과를 구분한다. 전체 서비스 시험은 실제 OCR·검색을 연결하고 따로 보고한다. CLIP 추가 비교는 선택 사항이며 필수 실험을 대체하지 않는다.

실험마다 목적·가설·설정·고정 조건·자료 버전·정답 근거·실제 결과·실패 예시·채택 여부·한계를 작성한다. 질문별 원시 결과와 실행 명령을 함께 보관한다. 근거는 청크 번호만이 아니라 원문 위치에 연결해 청크 크기별 비교가 가능하게 한다.

생성 품질은 Accuracy, Faithfulness, Relevance를 분리해 평가한다. 계산과 채점 기준은 통합 기획서의 정의를 사용하고 다음을 함께 기록한다.

- Accuracy: 정답 기준 충족 응답 수 ÷ 평가 질문 수 ×100.
- Faithfulness: 근거가 지지하는 사실 주장 수 ÷ 평가 가능한 사실 주장 수 ×100.
- Relevance: 질문별 관련성 점수 합 ÷ (2×평가 질문 수) ×100. 0=무관, 1=부분 관련, 2=직접 답함.

이는 프로젝트 채점 규칙이며 측정 결과가 아니다. 사실 주장 없는 보류를 충실도 만점으로 계산하지 않는다. 분모가 없으면 해당 없음으로 처리한다. 사람 판정과 LLM 판정을 구분하고 실제 측정하지 않은 개선 수치를 쓰지 않는다.

- [ ] 문서 출처의 페이지·섹션과 사진 원본 링크를 구분해 확인할 수 있다.

- [ ] 모바일·키보드·긴 텍스트·화면 새로고침을 확인한다.

## 7. 전달 위치와 완료 보고

하나의 저장소에서 frontend/에는 프론트 코드, backend/에는 백엔드·실험 코드를 둔다. 문서는 docs/frontend/, docs/backend/, docs/experiments/, docs/shared/로 역할을 나누는 기본안이다. 공통 문서는 기준 위치를 한 곳으로 정하고 나머지는 해당 버전 링크로 연결한다. 문서가 서로 다른 API를 설명하지 않게 한다.

README에는 실행법과 문서 목차를 제공한다. 문서별 현재 상태, 작성·검증 일자, 관련 커밋·명세 버전, 시험 환경, 미해결 이슈를 기록한다. 민감한 정보가 담긴 원본 데이터·토큰은 제출 파일에 포함하지 않는다.

완료 보고는 ‘생성·수정한 파일’, ‘실제 실행한 검사’, ‘확인된 결과’, ‘미완료·제약’으로 작성한다. 만들어야 할 산출물 목록을 이미 완성한 파일 목록으로 제시하지 않는다.


## 단일 저장소의 공통 Git 작성자 규칙

아래 규칙을 구현 저장소 루트 AGENTS.md에 한 번 작성하여 frontend/와 backend/에 공통 적용한다. 하위 폴더의 안내 문서에는 필요할 때 해당 파일을 참조한다. 현재는 기획서에 요구사항을 반영한 것이며 실제 저장소의 AGENTS.md를 생성한 것은 아니다.

- 커밋 author와 committer는 사용자가 지정한 이름·이메일을 사용한다.
- GPT·Codex·Claude 및 기타 AI·봇 명의로 커밋하지 않고 AI·봇 공동 작성자 표기를 추가하지 않는다.
- 커밋 전에 실제 적용되는 작성자 정보를 확인한다. 정보가 없거나 사용자 지정 정보와 다르면 커밋을 중단하고 확인한다.
- 사용자 승인 없이 Git 작성자 설정을 바꾸거나 환경 변수로 덮어쓰지 않는다.
- push는 사용자가 승인한 GitHub 계정으로만 수행한다.

CI는 변경 경로에 따라 프론트·백엔드 검사를 선택하고, 공통 계약·루트 설정이 변경되면 관련 검사를 모두 실행한다. 폴더 분리는 Git 저장소나 작성자 계정을 분리한다는 뜻이 아니다.
