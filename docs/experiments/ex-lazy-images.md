# 사진 검색도 지연 로딩으로 전환 — 계획서 요구사항 의도적 이탈

날짜: 2026-09-13 · 상태: 사용자 결정으로 채택

## 문제

메뉴 추출 후 항목마다 자동으로 참고 사진을 검색하다 보니(13개 메뉴
기준 항목당 1~2콜), 전체 분석이 "나머지 메뉴를 분석 중이에요" 상태로
오래 머물렀다. 이미 설명(description)은 "물어봤을 때만 생성"으로
바꿨는데(ex-lazy-description 참고), 사진은 여전히 자동이라 병목이
남아있었다.

## 계획서와의 충돌 (명시적으로 인지하고 넘어감)

- `frontend_plan.md`: "사진은 사용자 클릭 없이 자동 검색되고 준비된
  항목부터 표시"
- `menu_project_plan.md` 3절: "자동 사진 검색 ... 클릭 없이 시작"

이번 변경은 이 요구사항을 **의도적으로 뒤집는다**. 사용자에게 이
충돌을 두 번 명시적으로 알렸고("Tabelog" 논의 때, 그리고 이번 실제
적용 직전), 사용자가 "그게 더 좋다"고 확정했다(2026-09-13). 계획서
문서 자체는 수정하지 않는다(AGENTS.md 규칙 — frontend_plan.md는
읽기 전용).

## 변경 내용

- `backend/graph.py`: 추출 직후 모든 항목을 바로 `done` 상태로 전환
  (사진 검색 없이). 사진·설명 둘 다 채팅 메시지가 그 항목을 실제로
  참조할 때만 지연 생성 — describe() 먼저(경고 목록을 통째로 덮어써서
  images()가 남긴 "사진 없음" 경고를 지우면 안 되므로 순서 고정),
  그다음 images()
- `backend/targets.py`: `needs_images()` 추가. `images == []`만으로는
  "시도 안 함"과 "시도했지만 못 찾음"을 구분 못 해서, 두 provider가
  공유하는 경고 문자열(`NO_IMAGE_FOUND_WARNING`)로 구분한다
- 프론트(`AnalysisPage.tsx`): 칩·사진 핀을 탭하면 카드를 펼치는 동시에
  설명+사진을 함께 요청(`selectItem`). 이전에 "그냥 카드 모양만
  보고 싶은데 매번 과금된다"는 이유로 한 번 되돌렸던 동작인데, 이번엔
  사진도 지연 로딩이라 "탭 = 이 메뉴를 보겠다는 확정 의사"가 되므로
  다시 붙였다

## 실측 효과

격리된 mock 백엔드+프론트로 확인: 분석 완료까지 약 1.1초(이전에는
항목 수만큼 순차 단계 필요), "나머지 메뉴를 분석 중이에요" 표시가
전혀 뜨지 않음, 칩 한 번 탭으로 설명·사진 상태(참고 사진 없음 경고
포함)가 함께 로딩됨을 확인.

## 남은 한계

- 사진을 한 번도 안 눌러본 메뉴는 사진이 영원히 없다 — 계획서가
  원했던 "모든 메뉴에 자동으로 참고 사진"이라는 완결성은 포기했다.
  포트폴리오 평가 시 이 이탈을 설명해야 한다
- 토큰 비용은 사용자가 실제로 얼마나 많은 항목을 눌러보느냐에 따라
  달라진다 — 다 눌러보면 자동 방식과 총 호출 수가 비슷해지고, 일부만
  보면 그만큼 절약된다. 실측 비교(자동 대 지연)는 아직 안 했다
